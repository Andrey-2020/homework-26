# ADR-001 — WSS для realtime и REST для синхронизации истории

- **Статус:** Accepted
- **Контекст:** сообщения и статусы должны появляться у онлайн-пользователей быстро. Частый HTTP polling создаёт лишние запросы и задержку; WebSocket-соединения могут разрываться при смене сети или перезапуске приложения.

## Решение

Клиент поддерживает WSS-соединение с Realtime Gateway. Управление группами, приглашения, upload URL и получение истории выполняются через HTTPS REST. При reconnect клиент отправляет cursor последнего сообщения и догружает пропуски через `GET /v1/chats/{chatId}/messages` или `POST /v1/chats/sync`.

## Последствия

**Плюсы:** realtime-доставка без polling; отдельно масштабируется количество соединений; reconnect не зависит от сохранения состояния в gateway.

**Минусы/риски:** нужны heartbeat, backpressure, лимит соединений, reconnect jitter и защита от reconnect storm. Gateway не хранит единственную копию сообщения.

## Альтернативы

- HTTP polling: проще, но резко увеличивает RPS и добавляет задержку.
- SSE: однонаправленный поток не покрывает двустороннюю отправку и receipts так удобно, как WebSocket.
