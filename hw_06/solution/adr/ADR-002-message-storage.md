# ADR-002 — DynamoDB для сообщений, PostgreSQL для пользователей и групп

- **Статус:** Accepted
- **Контекст:** Message Store получает около 21,6 млн новых сообщений в сутки, хранит историю по чату/времени и должен горизонтально масштабироваться. При этом users, groups и membership имеют реляционные связи и требования к целостности.

## Решение

Identity и Chat metadata хранятся в отдельных PostgreSQL Multi-AZ кластерах. Сообщения и read cursors хранятся в DynamoDB. Partition key сообщения включает `chat_id` и месячный bucket; sort key включает серверное время и `message_id`. Срок хранения сообщения — 2 года. Медиа лежит в S3 отдельно.

## Последствия

**Плюсы:** разделены OLTP-данные и высокочастотная история; message read идёт по ключу чата; storage scale не требует ручного добавления PostgreSQL shards.

**Минусы/риски:** нет произвольных JOIN и полнотекстового поиска из коробки; дизайн обязан следовать ключевым access patterns. Очень активный чат может вызвать hot partition; лимит группы 300 и per-chat rate limit снижают риск.

## Альтернативы

- PostgreSQL для всего: проще старт, но большой message write-path, индексы и история конкурируют с membership transactions.
- Cassandra/ScyllaDB: подходит для wide-column событий, но требует отдельной эксплуатации/настройки кластера; для MVP управляемый DynamoDB уменьшает операционную нагрузку.
